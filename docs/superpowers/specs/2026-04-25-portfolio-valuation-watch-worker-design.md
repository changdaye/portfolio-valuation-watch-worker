# portfolio-valuation-watch-worker 设计文档

日期：2026-04-25

## 1. 目标

构建一个独立的 Cloudflare Worker，用于围绕当前投资组合暴露的**主题板块估值**与**宏观价格位置**生成日报，并在进入极端区间时额外推送飞书提醒。

项目目标不是复刻逐只持仓监控，而是把持仓所代表的风险暴露和风格暴露抽象成少量高价值的主题板块与宏观观察对象，形成每天可快速浏览的一份组合观察日报。

## 2. 已确认范围

### 2.1 推送与运行节奏

- 运行日：每周一到周六
- 运行时间：22:30（Asia/Shanghai）
- 推送形式：
  - 每日固定发送 1 条日报
  - 当对象首次进入极端区间时，额外发送 1 条预警

### 2.2 分位规则

- 历史窗口：近 5 年
- 默认极端阈值：
  - 低位极端：<= 10%
  - 高位极端：>= 90%

### 2.3 主题板块（由持仓合并）

1. 港股互联网 / 科技
2. 港股宽基
3. 医药 / 创新药 / 生物科技
4. 半导体 / 芯片
5. 红利 / 高股息
6. A 股大盘蓝筹
7. A 股中盘
8. 科创成长
9. 创业板成长
10. 美股科技
11. 美股宽基

### 2.4 宏观观察对象

1. DXY
2. USD/CNH
3. USD/JPY
4. 黄金
5. WTI 原油
6. 布伦特原油

### 2.5 指标口径

- 主题板块：优先观察 **PE 分位**、**PB 分位**
- 宏观观察：只观察**价格**与**5 年价格分位**
- 如果某个主题没有稳定直接的 PE/PB 数据：
  - 优先寻找相同主题的估值口径
  - 若不可得，则改用与持仓暴露最接近的代表指数 / ETF 作为代理
  - 若只拿到 PE 或只拿到 PB，则只展示真实可得指标，不补假数据

## 3. 非目标

第一版明确不做：

- 盘中监控
- 分钟级 / 小时级提醒
- 按持仓权重精确计算组合加权估值
- OCR 读取持仓截图
- 可视化 Web 后台
- 付费数据源优先接入
- 为不可比较资产强行补 PE/PB

## 4. 输出契约

### 4.1 飞书短消息

短消息保持当前既有偏好：

- 不显示顶部标题
- 不显示时间
- 不显示源帖链接
- 保留“关注代码”与精简摘要
- 如果有详细版报告，在结尾使用两行格式追加：

```text
详细版报告:
<URL>
```

推荐结构：

1. 今日结论
2. 主题板块摘要
3. 宏观观察摘要
4. 关注代码

### 4.2 详细版报告

详细版 Markdown 报告上传对象存储；key 规则：

- 前缀：`portfolio-valuation-watch-worker/`
- 文件名：UTC 时间戳 `YYYYMMDDHHMMSS.md`

推荐内容：

- 今日总览
- 极端项目汇总
- 主题板块估值表
- 宏观观察价格分位表
- 代理映射说明
- 每个对象的数据日期（as of）
- 缺失 / stale 数据说明

## 5. 数据新鲜度与提醒规则

### 5.1 新鲜度

- 每个对象独立记录 `asOfDate` 与 `fetchedAt`
- 日报允许展示“最新可得数据”
- 旧数据可以展示，但必须带日期说明
- stale 数据不得触发新的极端提醒

### 5.2 极端提醒

#### 主题板块

当出现任一条件时触发极端提醒：

- PE 分位 <= 10%
- PE 分位 >= 90%
- PB 分位 <= 10%
- PB 分位 >= 90%

规则：

- 同一主题同一轮次只发 1 条提醒
- 持续停留在极端区时不重复提醒
- 只有首次进入极端区时提醒
- 退出后再次进入，才允许重新提醒

#### 宏观对象

当价格分位出现下列情况时提醒：

- 价格分位 <= 10%
- 价格分位 >= 90%

对象包括：DXY、USD/CNH、USD/JPY、黄金、WTI、布伦特。

## 6. 系统架构

### 6.1 运行组件

- Cloudflare Worker + Cron：定时执行日报与预警判断
- D1：保存监控对象、历史快照、计算结果、通知记录
- KV：保存运行时状态、极端提醒去重状态、失败计数等
- Workers AI：生成简短中文摘要；失败时回退规则模板
- 对象存储：上传详细 Markdown 报告
- Feishu：发送日报与极端提醒

### 6.2 第一版执行方式

第一版不使用 Queue，原因如下：

- 监控对象总数不大（约 20 个以内）
- 单次任务内并发抓取足够
- 更贴近现有两融项目的一次性汇总模型

推荐主流程：

1. 载入默认监控对象清单
2. 并发抓取全部对象数据
3. 归一化为统一快照
4. 基于 D1 历史数据计算 5 年分位
5. 生成状态与极端标记
6. 持久化快照与信号
7. 生成详细报告并上传
8. 发送日报
9. 发送新增极端提醒
10. 更新 KV 运行状态

## 7. 数据源策略

### 7.1 主题板块

每个主题板块定义：

- `displayName`
- `sourceHoldings`
- `proxyName`
- `proxyCode`
- `metricMode = valuation`
- `supportsPE`
- `supportsPB`

数据抓取策略：

- 优先使用主题本身的稳定估值来源
- 无稳定口径时，改用最接近持仓暴露的代表指数 / ETF
- 如果代理明显不合适，则返回 unavailable，而不是伪造数据

### 7.2 宏观对象

每个宏观对象定义：

- `displayName`
- `symbol`
- `metricMode = price`

数据抓取策略：

- 只抓最新价格与历史价格序列
- 不做 PE/PB
- 基于历史序列计算价格分位

## 8. 存储设计

推荐最小核心表：

1. `watch_items`
   - 监控对象定义与默认映射
2. `daily_snapshots`
   - 原始标准化结果（PE / PB / 价格 / 数据日期等）
3. `daily_signals`
   - 分位、状态、是否极端等计算结果
4. `notification_runs`
   - 日报、预警、心跳、失败告警发送记录

KV 中保存：

- 最近一次成功运行时间
- 最近一次失败信息
- 每个对象最近一次极端状态与提醒时间

## 9. 异常处理与降级

- 单个对象抓取失败：
  - 标记 unavailable
  - 日报继续发送
  - 报告中展示失败原因
- 数据 stale：
  - 允许展示
  - 不触发新提醒
- AI 摘要失败：
  - 回退规则模板
- 报告上传失败：
  - 日报仍可发送
  - 明确说明详细报告上传失败
- 大面积失败：
  - 不发正常日报
  - 改发失败告警
